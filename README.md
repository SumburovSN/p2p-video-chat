Приложение p2p-video-chat это frontend приложение на react для установления видеосвязи между двумя браузерами.
Основано на PeerJS - JavaScript-библиотеке, которая оборачивает технологию WebRTC и позволяет связывать браузеры пользователей напрямую (Peer-to-Peer или P2P).
Процесс функционирования PeerJS:

1. Этап сигнального сервера (Поиск друг друга)

Браузеры не могут связаться напрямую, пока не узнают IP-адреса друг друга. Для этого нужен «посредник» — сигнальный сервер (PeerServer).
• Регистрация: Клиент А подключается к сигнальному серверу и получает уникальный текстовый ID (или генерирует свой).
• Запрос связи: Клиент Б хочет связаться с Клиентом А. Он отправляет запрос на сервер, зная ID Клиента А.
• Обмен метаданными: Сервер помогает клиентам обменяться техническими данными о сети (так называемыми ICE-кандидатами и SDP-офферами), чтобы они поняли, как достучаться друг до друга в обход роутеров и NAT.
ICE - Interactive Connectivity Establishment
SDP - Session Description Protocol
NAT - Network Address Translation

2. Прямое соединение (Peer-to-Peer)

Как только браузеры получили координаты друг друга, сигнальный сервер выходит из цепочки. Передача данных теперь идет напрямую от пользователя к пользователю.

3. Каналы передачи данных

PeerJS позволяет открывать два типа потоков:
• DataConnection (Данные): Создает текстовый/бинарный канал. Через него с помощью метода .send() можно мгновенно передавать строки, JSON, файлы или игровые состояния.
• MediaConnection (Медиа): Используется для стриминга аудио и видео. Вы передаете поток с веб-камеры или микрофона, а другой пользователь принимает его и вставляет в тег <video> или <audio>

Приложение использует MediaConnection.

Процесс формирование пути от одного клиента к другому называется ICE (Interactive Connectivity Establishment) и осуществляется методом «от простого к сложному» через  три основных сценария:
```
[Клиент А] <--- (1. Прямой путь / 2. STUN сервер) ---> [Клиент Б]
      \                                                   /
       \---> [3. TURN сервер (если сеть заблокирована)] <---/
```

Шаг А: Сбор кандидатов (Поиск своих адресов)

Каждый браузер пытается понять, под какими адресами его видно в сети.
1. Он смотрит свои локальные сетевые интерфейсы.
2. Он делает быстрый запрос к STUN-серверу (Session Traversal Utilities for NAT). STUN-сервер — это просто «зеркало». Браузер спрашивает его: "С какого IP и порта к тебе пришел мой запрос?", и STUN возвращает ему его внешний (публичный) IP и порт. PeerJS по умолчанию использует бесплатные STUN-серверы от Google.

Шаг Б: Обмен и проверка путей (Пинг-понг)

Клиенты через сигнальный сервер обмениваются всеми найденными адресами (ICE-кандидатами). После этого они начинают одновременно «пинговать» адреса друг друга, проверяя, какие из путей работают. В приоритете всегда самый прямой и быстрый путь:
1. Прямой локальный путь (Host): Если клиенты находятся в одной Wi-Fi сети, они моментально соединяются по внутренним IP (например, 192.168.x.x). Трафик даже не выходит в интернет.
2. Прямой публичный путь (Server Reflexive): Браузер пытается отправить UDP-пакет на публичный IP-адрес другого клиента. Если домашние роутеры (NAT) у обоих пользователей не слишком строгие, они пробивают «туннель» и соединяются напрямую. Это происходит примерно в 70–80% случаев в обычном домашнем интернете.

Шаг В: Запасной путь (Реле / TURN)

Если оба клиента сидят за строгими корпоративными файрволами или симметричными NAT (Symmetric NAT), которые запрещают входящие соединения в обход правил, прямое соединение установить невозможно.
Тогда WebRTC задействует TURN-сервер (Traversal Using Relays around NAT).
• В этом случае путь формируется не напрямую, а через сервер-посредник.
• Клиент А отправляет данные на TURN-сервер, а сервер пересылает их Клиенту Б (и наоборот).
• Важно: PeerJS не предоставляет бесплатные TURN-серверы «из коробки», так как они гонят через себя весь трафик и требуют много ресурсов. Для коммерческих проектов их приходится разворачивать самостоятельно (например, на базе coturn).

### Состав серверов на VDS:

```text
VDS
│
├── nginx :443
│     ├── React
│     ├── /myapp/ → PeerJS :9000
│     └── /api/   → Room Manager :9100
│
├── PeerJS :9000
├── Room Manager :9100  ← systemd
└── coTURN
```

### Схема установления связи между 2-мя браузерами с использованием Room Manager

```text
Первый                         Room Manager
  │                                │
  │ join AAA111                    │
  ├───────────────────────────────>│
  │ waiting                        │
  │<───────────────────────────────┤
  │                                │
  │ wait AAA111                    │
  ├───────────────────────────────>│
  │ waiting                        │
  │<───────────────────────────────┤
  │                                │
  │             второй входит      │
  │                         BBB222 │
  │                                │
  │ wait AAA111                    │
  ├───────────────────────────────>│
  │ connected + BBB222             │
  │<───────────────────────────────┤
```
### Инструкция по установке приложения на VDS
Лучше разделить исходники проекта и готовый сайт:
```
/opt/
└── p2p-video-chat/       ← Git-репозиторий

/var/www/
└── p2p-video-chat/       ← готовый React dist
```
То есть:
```
/opt/p2p-video-chat       ← Git-репозиторий, исходники
        │
        │ npm install
        │ npm run build
        ▼
/opt/p2p-video-chat/dist  ← готовый React
        │
        ▼
      Nginx :443
        │
        ├── /        → React
        │
        └── /myapp/  → PeerJS :9000
```

```console
cd /opt
sudo git clone https://github.com/SumburovSN/p2p-video-chat.git
```
```console
cd /opt/p2p-video-chat
```
```console
npm ci
```
```console
npm run build
```
1. Создаём каталог сайта
```console
sudo mkdir -p /var/www/p2p-video-chat
```
2. Копируем собранный React
```console
sudo cp -r /opt/p2p-video-chat/dist/* /var/www/p2p-video-chat/
```
3. Перед изменением Nginx сохраним текущую конфигурацию
*Бэкап лучше хранить не в sites-enabled, а, например, в /root/nginx-backups.*
```console
sudo cp /etc/nginx/sites-enabled/peerjs \
        /etc/nginx/sites-enabled/peerjs.backup
sudo mkdir -p /root/nginx-backups
sudo mv /etc/nginx/sites-enabled/peerjs.backup /root/nginx-backups/
```
